2. Messages Upsert Handler (196 lines)
   File: app/services/whatsapp/whatsmeow_handlers/messages_upsert.rb

     - Extract messages array from webhook data
     - Determine direction: incoming or outgoing
     - Use Redis lock to prevent race conditions
     - Validate message not duplicate

     - Check JID type (user, group, LID, etc.)
     - Create/find contact from phone number
     - Create/find conversation
     - Build message with content attributes
     - Download and attach media if present
     - Update contact avatar from profile picture

     * text, image, video, audio, file, sticker, reaction, contact
     * protocol (ignored), context (ignored), edited, unsupported

3. Messages Update Handler (122 lines)
   File: app/services/whatsapp/whatsmeow_handlers/messages_update.rb
   
   Process: process_messages_update()
     - Extract update array from webhook
     - Find message by source_id
     - Update status with Redis lock
     - Handle edited messages
   
   Status Mapping:
     * sent, pending, server_ack → 'sent'
     * delivered, delivery_ack → 'delivered'
     * read → 'read'
     * failed, error → 'failed'
   
   Status Transitions:
     * read messages cannot revert
     * delivered cannot downgrade to sent
     * Updates agent_last_seen_at if incoming read

9. INTEGRATION FLOW SUMMARY
================================================================================

CONNECTION FLOW:
  1. User creates channel via Web UI
  2. Channel::Whatsapp record created with provider=whatsmeow
  3. User initiates setup
  4. WhatsappWhatsmeowService#setup_channel_provider called
  5. POST /instances (create) + POST /connect (QR generation)
  6. Whatsmeow API returns QR code in response
  7. provider_connection updated with connection state + QR data
  8. User scans QR with phone
  9. WhatsApp connects, Whatsmeow emits connection.update webhook
  10. connection state changes: connecting → open
  11. Channel ready for messaging

MESSAGE RECEPTION FLOW:
  1. User sends message to bot WhatsApp number
  2. Whatsmeow API receives via WhatsApp protocol
  3. Whatsmeow emits messages.upsert webhook event
  4. POST /webhooks/whatsapp/:phone_number
  5. WhatsappController validates token + queues job
  6. WhatsappEventsJob finds channel, routes to IncomingMessageWhatsmeowService
  7. MessagesUpsert handler processes message
  8. Contact & conversation created/found
  9. Message record created with attachments
  10. WebSocket updates UI in real-time

MESSAGE SENDING FLOW:
  1. Agent replies via Chatwoot UI
  2. Message record created with status: pending
  3. SendReplyJob queued
  4. WhatsappWhatsmeowService#send_message called
  5. Routes to send_text_message() or send_media_message()
  6. HTTP POST to /instances/:id/messages/send/{type}
  7. Whatsmeow API sends to WhatsApp servers
  8. Response includes message_id
  9. Message updated with external_created_at + source_id
  10. Whatsmeow emits messages.update webhook with status
  11. Message status updated: pending → sent → delivered → read
  12. UI updates via WebSocket

STATUS TRACKING FLOW:
  1. Outgoing message sent (status: sent)
  2. Whatsmeow API monitors WhatsApp protocol
  3. Whatsmeow emits messages.update webhook
  4. MessagesUpdate handler processes status
  5. Find message by source_id
  6. Update status with state machine validation
  7. If read: update agent_last_seen_at timestamp
  8. UI shows message status in real-time

CONNECTION UPDATE FLOW:
  1. Device goes offline
  2. Whatsmeow detects connection loss
  3. Emits connection.update webhook
  4. ConnectionUpdate handler processes
  5. provider_connection updated with error
  6. Connection state: open → close
  7. UI displays connection error to admin
  8. Manual reconnect or auto-recovery
